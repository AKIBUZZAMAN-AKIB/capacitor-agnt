নতুন Skill

কীভাবে ব্যবহার করবেন

Skill তৈরি হলে নিচের তালিকায় Start চাপুন। আলাদা session তৈরি হবে—সেই session থেকে chat চালাতে চাইলে chat history থেকে সেটি খুলুন। Automation ও Heartbeat form-এ Saved Skill বেছে নিতে পারবেন; engine সেই Skill-এর tool allow-list ও timeout মেনে চলবে।

OAuth ও নিরাপত্তা

OAuth-চালিত MCP server-এর জন্য আগে server-এর browser/OAuth flow-এ consent শেষ করে পাওয়া access token দিন। Token শুধুই নির্দিষ্ট server-এর নামে নিরাপদ storage-এ রাখা হয় এবং chat/transcript-এ লেখা হয় না।

MCP server-এর tool description ও ফলাফল বাইরের input—তাই এগুলোকে নির্দেশ হিসেবে বিশ্বাস না করে approval ও tool policy-র মধ্যে রাখুন।

সর্বশেষ 2026-07-28 MCP stateless HTTP, route headers ও stronger authorization ব্যবহার করে; পুরোনো server-এ auto mode legacy fallback চেষ্টা করে।

Provider, model & auto-routing

Model তালিকা live catalog থেকে আনুন। নিচের default model ও base URL provider configuration; উপরের model field শুধু এই turn-এর override। Save করলে model-level tool/protocol/auth/stream capability ও fallback order runtime settings-এ থাকে; API key আলাদা auth store-এ যায়। Auto mode-এ turn override কেবল নির্বাচিত catalog provider-এ যাবে—পূর্ণ auto-routing চাইলে উপরের override ফাঁকা রাখুন। Free-tier model-এর prompt logging/training ঝুঁকি catalog-এ থাকলে এখানে দেখানো হবে।

Catalog model metadata এখানে দেখানো হবে।

Tool call থাকবে এমন task কেবল model-level-এ verified tool support থাকা route-এ যাবে। Stream শুরু হলে retry/failover বন্ধ—partial উত্তর duplicate হবে না। Auth/invalid request-এ অন্য provider-এ নির্বিচারে fallback হবে না।

WebLLM WebView-এর WebGPU ব্যবহার করে; browser module CDN থেকে load হতে পারে, model weights প্রথমবার নামতে পারে। iOS/Android WebView-এ WebGPU না থাকলে local provider ব্যবহারযোগ্য নাও হতে পারে।

PER-APP POLICY
App policy

          
        

        
        
Ask হলে call অপেক্ষা করবে; Allow/Block stored decision ভবিষ্যৎ call-এ স্বয়ংক্রিয় হবে। Ask বা Block করলে সংশ্লিষ্ট live subscription/resource revoke করা হয়।

        

        

          
Network mode

          
sandboxed = আগেভাগে সব remote request বন্ধ · hosts = শুধু approved host · full = পুরো ইন্টারনেট খোলা (HTTPS/WSS + ফর্ম)। Full mode-এ app-টা তার পাওয়া native data বাইরে পাঠাতে পারে — শুধু বিশ্বস্ত app-কে দিন। প্রতিটা request-এর হিসাব নিচে usage-এ দেখা যায়।

          

            
            
          

          
⚠️ FULL mode চালু: এই app সব HTTPS/WSS host-এ যেতে পারবে। Camera/files/location capability দিলে সেই data-ও বাইরে যেতে পারে।
